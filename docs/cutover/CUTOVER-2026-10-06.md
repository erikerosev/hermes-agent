## Két javítás kellett hozzá, mindkettő a cutover közben derült ki

### 1. `context_management: Extra inputs are not permitted` (HTTP 400)

A native CLI egy `context_management` top-level mezőt küld a Messages API-nak, amit
az API elutasít. Minden TOOL-os forduló 400-azott (az egyszerűek átmentek), a plugin
3× újrapróbálta, majd `error_max_turns`-szel elhasalt.

Javítás a plugin relayében (`admission.py`): `strip_unsupported_fields()` kiveszi a
top-level `context_management`-et, mielőtt a relay továbbítja. A relay amúgy is
átírja a payloadot (`pin_message_breakpoint`), tehát ez odavaló.
**A javított fájl másolata: `docs/cutover/admission.py.patched`** — a plugin a
`~/.hermes/plugins/` alatt él, NEM verziókezelt; újratelepítés után ÚJRA KELL
alkalmazni. Upstreamnek jelenthető (a plugin 2.1.263-ra kvalifikált, mi 2.1.276-ot
futtatunk).

### 2. Elavult `claude` bináris a unit PATH-ján — MÁSODSZOR

A systemd unit PATH-ja `/home/eeros/.hermes/agent-venv/bin:/usr/local/...`, és NEM
tartalmazza a `~/.local/bin`-t. A PATH-on viszont ott volt `/usr/bin/claude` →
**2.1.49**, egy ~2 évvel régebbi bináris, és a plugin AZT használta.

Ez pontosan ugyanaz a csapda, amit a `gateway-stale-claude-binary` memória már
feljegyzett (2.1.49 vs 2.1.241) — most a pluginon keresztül ütött újra.

Javítás: `/etc/systemd/system/hermes-fenris.service.d/cutover-0215-claude.conf`
```
Environment=CLAUDE_SUBSCRIPTION_DIRECTSDK_COMMAND=/home/eeros/.local/bin/claude
Environment=PATH=/home/eeros/.local/bin:/home/eeros/.hermes/agent-venv/bin:...
```
